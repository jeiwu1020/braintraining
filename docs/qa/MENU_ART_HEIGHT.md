# 五款桌遊選單圖區高度與取景

本項以 `6fef10ac4c3cd8ceebd1f64d45e3c9104169dced` 為基準，只調整選單圖區高度與cover取景。夜市手機遊戲內布局另見 `NIGHT_MARKET_LANDSCAPE_LAYOUT.md`，兩項保留獨立diff及驗證證據。

## 原因與調整

基準 `table-games.css` 為五張新圖加了 `aspect-ratio:4/3;flex:none`，夜市圖區則沿用共用 `flex:1` 與最小高度。五款因此會依寬度撐出過高圖片。共用卡片最小高度與同列拉伸也會在描述換行時，讓不同卡片的剩餘空間落在圖片上；這在320px直向與640px橫向可實際重現。

- 移除五圖的固定4:3圖框、flex:none與特殊background-origin，回到夜市同一套共用圖區尺寸規則。
- 卡片按內容自然排高，取消卡片最小高度／列內拉伸對圖片的影響。標題或描述可完整換行，整卡高度可以因文字而不同；比較的是圖片區高度，沒有拿整卡高度代替。
- 夜市與築牆的圖像來源及所有WebP原檔保持不變；共用卡片的自然排高也會解除它們被同列其他卡片間接撐高的情況。
- 圖片仍用 `background-size:cover` 等比裁切，不壓扁、不重生圖片、不改五張1000×750原WebP。下方h2、描述與操作名稱保留，沒有恢復圖上的重複標題span。

## 圖片區量測

調整前，1440×900桌面夜市圖區140px、五張新圖約366.4px；1280×800時五張約321.4px；844／896／932橫向時五張分別約216.1／231.1／241.5px。直向時固定比例還會透過共用格列間接撐高夜市／築牆圖片，不能只看單張圖的尺寸宣告。

調整後，桌面、320／390直向及一般橫向各圖區沿用140px；844×320較短橫向沿用共用96px。五張新圖每一項都與同視窗夜市實測高度一致。文字標籤的換行不再把圖片撐高。

`docs/qa/menu-art-height-browser.mjs` 逐圖解碼、量測實際 `pg-box-art`、比較Night Market圖區，而非整卡：

- 桌面1440×900、1280×800；直向320×568、390×844。
- 橫向640×360、768×353、844×320、844×390、896×414、932×430。
- 共50組五圖高度／flex／aspect規則比對；驗證cover、1000×750解碼、完整標題／描述、零重複圖區span及無頁面溢出。
- 保存每個視窗的夜市、築牆與五款卡片前後截圖；逐張人工檢查桌面及手機裁切。
- 既有 `tabletop-rules-browser.mjs` 改為比對夜市圖區高度，仍驗證HTTP200、WebP格式、1000×750原圖及五款規則視窗流程。

最終production preview的50組圖區檢查全部通過，五款既有桌遊另通過100組規則視窗及25組圖片／高度回歸；未預期的瀏覽器錯誤為0。外部字型與favicon的既有資源錯誤另記於原始JSON，不作為新圖載入成功的替代訊號。

`public/playground/ASSETS.md` 已區分原圖4:3與選單框的cover裁切。此項不改遊戲內資源、規則、計分或AI。完整驗證結果與兩項獨立diff列於本批審查包總報告；截圖為Chromium模擬，實體iOS仍待驗收。
