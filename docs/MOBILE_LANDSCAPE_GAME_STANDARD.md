# 手機橫向遊戲版面規格

本專案以手機橫向為第一優先。新增遊戲或整理既有遊戲時，應先在橫向窄高度完成，再補直向與桌面呈現。

## 1. 支援範圍與驗證尺寸

- 最低支援視窗：`640 × 360`。
- 主要設計基準：`844 × 390`。
- 大型手機驗證：`932 × 430`。
- 另以 `390 × 844` 確認直向不會無法操作，但直向不是主要版面。
- 內容須避開瀏海與 Home Indicator，使用 `env(safe-area-inset-*)`。

## 2. 共用頁面骨架

標準遊戲頁使用 `components/game-ui/GameShell.tsx`：

1. 整頁固定為 `100dvh`，不讓文件本身上下捲動。
2. 頁首固定包含返回鍵、遊戲名稱，可選擇顯示副標、狀態與次要操作。
3. 返回鍵與圖示操作必須有可辨識的 `aria-label`。
4. 主遊戲區使用 `flex: 1`、`min-height: 0`；只有紀錄、清單或說明區可局部捲動。
5. Modal 或教學說明須限制最大高度並允許內部捲動。

沉浸式活動（呼吸、音景、曼陀羅、指尖星空）可隱藏一般頁首，但仍須提供至少 `44 × 44 px` 的固定返回控制，並自行套用安全區。

## 3. 五種版面預設

遊戲在 `data/gameCatalog.ts` 必須指定一種 `layoutPreset`：

| 預設 | 適用內容 | 橫向結構 |
| --- | --- | --- |
| `SPLIT_CHOICE` | 題目＋選項 | 左側題目，右側操作與選項；使用 `components/game-ui/SplitChoiceLayout.tsx` |
| `BOARD_SIDEBAR` | 棋盤、迷宮、桌遊 | 主棋盤佔較大區域，側欄放狀態與操作 |
| `GRID_FOCUS` | 配對、搜尋、拼圖 | 中央網格為主，資訊列保持精簡 |
| `FACILITATOR` | 團體帶領、故事、社交題 | 展示區與帶領控制分離，避免控制誤觸 |
| `IMMERSIVE` | 放鬆與感官活動 | 全畫面體驗，控制最少且可淡出 |

## 4. 尺寸與互動規則

- 主要觸控目標最小 `44 × 44 px`；相鄰主要操作至少保留 `8 px` 間距。
- 一般內文以 `16 px` 為目標；輔助標示不得小於 `12 px`。
- 首要操作應有文字；只有通用且清楚的返回、說明、重設等動作可只用圖示。
- 選取、答對、答錯不可只靠顏色區分，需搭配文字、圖示、外框或形狀。
- 動畫必須尊重 `prefers-reduced-motion`；重要訊息不可只在短暫動畫中出現。
- 需要捲動的區塊應保留可見線索，避免把提交、返回或下一題放在捲動末端。

## 5. 資料與導覽規則

- 遊戲名稱、一般／進階說明、內容分類、能力標籤、遊玩人數與版面預設，以 `data/gameCatalog.ts` 為單一資料來源。
- 首頁固定使用五個內容分類：認知訓練、棋盤與策略、卡牌與桌遊、生活／情緒與社交、放鬆與舒緩。
- 「團體」「引導者」屬於遊玩方式，不再作為互斥內容分類；未來可由 `playerModes` 做篩選。
- 新增 `GameState` 時必須同步加入目錄；目錄完整性由 `tests/gameCatalog.test.ts` 驗證。

## 6. 新遊戲完成條件

- [ ] 已加入單一遊戲目錄並填妥所有 metadata。
- [ ] 使用 `GameShell` 或符合沉浸式例外規格。
- [ ] 在 `640 × 360`、`844 × 390`、`932 × 430` 完成主要流程。
- [ ] 所有必要操作無需捲動整頁即可觸及。
- [ ] 觸控尺寸、鍵盤焦點、非純顏色提示與 reduced motion 均符合規格。
- [ ] 一般與進階的首頁說明、遊戲內容及說明文字一致。
- [ ] 通過單元測試、正式建置與至少一輪實機尺寸畫面檢查。

## 7. 既有遊戲遷移順序

先依共用程度逐批整理，避免一次重寫所有遊戲：

1. 題目＋選項類（`SPLIT_CHOICE`）。
2. 網格認知類（`GRID_FOCUS`）。
3. 棋盤類（`BOARD_SIDEBAR`）。
4. 團體帶領類（`FACILITATOR`）。
5. 沉浸式活動（`IMMERSIVE`）。

每批先選一個代表遊戲成為參考實作，再遷移同型遊戲。珠璣妙算是第一個採用共用 `GameShell` 的示範；快樂市集是 `SPLIT_CHOICE` 的參考實作。
